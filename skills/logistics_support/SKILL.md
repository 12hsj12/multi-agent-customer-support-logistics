# 物流纠纷受理规范（演示）

## 处理步骤

1. 区分疑似丢件、破损或错发、签收争议、配送延误、修改地址五类诉求。
2. 缺少运单号时先追问；不要猜测运单号，也不要要求身份证、完整手机号、密码或支付凭证。
3. 仅在用户提供运单号后调用 `query_logistics`。该工具只查询本地固定模拟数据，结果来源为 `local_mock`。
4. 说明查询结果是演示记录，不代表真实承运商轨迹。未知记录只请用户核对，不推断真实状态。
5. 破损或错发可建议保留外包装、面单和商品现状照片；签收争议可整理页面状态与用户实际收货情况。不得编造证据。
6. 地址修改、丢件认定、理赔金额和退款均需要真实业务系统或人工核验；当前系统不能执行这些操作。

## 升级边界

疑似丢件只有在本地模拟轨迹达到配置停滞天数，且最近五条历史消息中的同类物流用户追问达到配置数量时，才触发现有 `EscalationAgent`。默认值为 `ECHOMIND_LOGISTICS_LOST_DAYS_THRESHOLD=7`、`ECHOMIND_LOGISTICS_MIN_FOLLOWUPS=2`。这是可配置的演示规则；历史消息没有可靠时间戳，不能把追问计数说成真实时间频率或快递公司政策。

应用内交接摘要不等于已创建工单或已联系人工客服。回复需明确说明这一点。
