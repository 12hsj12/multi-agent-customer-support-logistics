# 智能客服多 Agent 协同决策系统架构

以下图表描述当前 Python 后端的运行结构与请求数据流。名称和行为以 api/、core/、agents/、mcp/、memory/ 的现有实现为准。

## 总体架构

```mermaid
flowchart LR
    C[用户 / 客户端] --> N[Nginx 可选入口]
    N --> API[FastAPI]
    C --> API
    API --> CHAT[/chat]
    API --> OPS[health · docs · skills · search · knowledge · monitor · metrics · trace · eval]

    CHAT --> MEM[MemoryManager]
    MEM --> REDIS[(Redis<br/>工作记忆 / 摘要)]
    MEM --> CHROMA[(ChromaDB<br/>情景记忆 / 用户画像 / knowledge_base)]

    CHAT --> INT[IntentRecognizer]
    INT --> TRI[LLM + 字符 n-gram + Pattern]
    TRI --> BASE[baseline 默认融合]
    BASE --> DEC{local 复核条件}
    DEC -->|高置信 LLM 优先| ROUTE[AgentOrchestrator]
    DEC -->|other / 低置信 / 冲突| MAP[Mapika GGUF<br/>CPU 本地决策]
    MAP -->|成功或回退 baseline| ROUTE
    BASE -->|默认关闭 local| ROUTE

    ROUTE --> GEN[GeneralAgent]
    ROUTE --> TECH[TechnicalAgent]
    ROUTE --> BILL[BillingAgent]
    ROUTE --> LOG[LogisticsAgent]
    ROUTE --> ESC[EscalationAgent]

    GEN --> SK[SkillManager<br/>按 Agent 和关键词注入]
    TECH --> SK
    BILL --> SK
    LOG --> SK

    GEN --> TOOLS[LLM Agent 工具白名单]
    TECH --> TOOLS
    BILL --> TOOLS
    LOG --> TOOLS
    TOOLS --> RAG[共享 search_knowledge_base<br/>Agent 按需调用]
    RAG --> TM[MCP ToolManager<br/>改写 / 召回 / 重排 / 缓存 / fallback]
    TM --> CHROMA
    TOOLS --> FIX[query_logistics<br/>data/mock_logistics.json]
    FIX -->|local_mock 候选升级| ESC
    ESC --> HAND[应用内交接结果<br/>无真实工单集成]

    ROUTE --> TRACE[request_id 工具轨迹]
    ROUTE --> MON[Monitor 与 Prometheus]
    ROUTE --> API
    MEM --> API
```

## /chat 调用顺序

```mermaid
sequenceDiagram
    participant U as 用户
    participant API as FastAPI /chat
    participant MEM as MemoryManager
    participant IR as IntentRecognizer
    participant DP as DecisionProvider
    participant OR as AgentOrchestrator
    participant AG as 主 / 辅 LLM Agent
    participant RAG as 共享知识检索工具
    participant LOG as 本地物流 mock
    participant ESC as EscalationAgent

    U->>API: message + user_id + 可选 conv_id
    API->>MEM: 读取最近消息、摘要、情景记忆、画像
    MEM-->>API: MemoryContext
    API->>IR: 消息 + 最近最多 5 条历史
    IR->>IR: LLM、字符 n-gram、Pattern 融合
    opt local 模式且未命中高置信 LLM 优先条件
        IR->>DP: 仅在 other / 低置信 / 冲突时复核
        DP-->>IR: 意图 / 置信信号 / 状态 / 耗时
    end
    IR-->>API: intent、intent_group、实体、紧急度、来源状态
    API->>OR: Request + MemoryContext
    OR->>OR: 计算主 Agent、辅助 Agent 和可用性降级
    OR->>AG: 执行一个或多个 Agent
    opt Agent 判断需要检索业务材料
        AG->>RAG: search_knowledge_base
        RAG-->>AG: 改写与重排后的结果或回退信息
    end
    opt 物流纠纷且有运单号
        AG->>LOG: query_logistics(tracking_no)
        LOG-->>AG: local_mock 状态与升级候选
        opt 本地规则满足
            OR->>ESC: 生成应用内交接结果
            ESC-->>OR: 交接说明 + escalated 标记
        end
    end
    AG-->>OR: 回复、工具调用与轨迹
    OR-->>API: 回复、路由、工具、request_id
    API->>MEM: 写入用户与助手消息
    API-->>U: ChatResponse
    API-)MEM: 异步更新用户画像
```

## 物流纠纷与人工交接

```mermaid
flowchart LR
    U[物流纠纷请求] --> I{识别细分意图}
    I --> L[LogisticsAgent]
    L --> F{是否有 tracking_no}
    F -->|否| ASK[先追问运单号]
    F -->|是| Q[query_logistics]
    Q --> SRC[固定本地 fixture<br/>source=local_mock]
    SRC --> C{丢件意图 + 停滞天数达阈值<br/>+ 最近 5 条历史中追问数达阈值}
    C -->|否| RESP[说明本地模拟记录与证据边界]
    C -->|是| ESC[EscalationAgent]
    ESC --> HAND[应用内交接结果<br/>不创建真实工单]
    RESP --> OUT[/chat 响应 + request_id/]
    HAND --> OUT
```

## 部署拓扑

```mermaid
flowchart TB
    CLIENT[客户端] -->|HTTP 80| NGINX[Nginx]
    CLIENT -->|HTTP 8000| APP[FastAPI 应用]
    NGINX -->|反向代理| APP
    APP -->|Redis URL| REDIS[(Redis 7)]
    APP -->|Chroma 读写接口| CHROMA[(ChromaDB 0.5.23<br/>默认 ONNX Embedding)]
    PROM[Prometheus] -->|抓取 /metrics| APP
    HOSTMODEL[宿主机 models/ GGUF<br/>Git LFS 获取] -->|只读挂载 /app/models<br/>仅 local 模式使用| APP
    APP -->|Anthropic 协议模型 API| LLM[外部 LLM 服务]
    APP -->|不发外部请求| MOCK[data/mock_logistics.json]
    JEV[官方 JEV<br/>尚未接通]
```

Compose 服务端口：API 8000、Nginx 80、ChromaDB 8001、Redis 6379、Prometheus 9090。models/*.gguf 被 .dockerignore 排除，Compose 将权重目录只读挂载给应用容器。完整启动步骤和变量说明见[完整使用指南](完整使用指南.md)。
