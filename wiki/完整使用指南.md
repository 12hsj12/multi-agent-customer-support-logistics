# 智能客服多 Agent 系统使用指南

本文介绍 Docker Compose 启动、baseline/local 决策切换、对话与物流演示、知识库、Skills、请求轨迹和监控评测。项目文档以仓库内 Python 后端为准。

## 1. 前置条件与配置

需要 Docker Desktop（含 Compose v2）、Git LFS，以及 Anthropic 或兼容 Anthropic Messages API 的 LLM 服务凭证。Mapika 本地决策器可选；官方 JEV 当前未接入。

从仓库根目录执行：

```bash
git lfs install
git lfs pull
cp .env.example .env
```

修改 .env：

```env
ANTHROPIC_API_KEY=替换为有效密钥
ANTHROPIC_BASE_URL=
ANTHROPIC_MODEL=claude-3-5-sonnet-20241022
REDIS_PASSWORD=替换为唯一随机密码
ECHOMIND_DECISION_BACKEND=baseline
```

对接兼容 Anthropic 协议的模型时，按服务方要求填写 ANTHROPIC_BASE_URL 与 ANTHROPIC_MODEL。变量名保留代码中的既有标识。不要把 .env 提交到仓库。

## 2. Docker Compose 启动

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f echomind
```

服务入口：

| 服务 | 地址 |
|---|---|
| API | http://localhost:8000 |
| Swagger | http://localhost:8000/docs |
| Health | http://localhost:8000/health |
| Nginx | http://localhost |
| ChromaDB | http://localhost:8001 |
| Redis | localhost:6379 |
| Prometheus | http://localhost:9090 |

常用停止/重启：

```bash
docker compose stop
docker compose restart echomind
```

Compose 启动依赖 Redis 与 ChromaDB 的健康检查。Dockerfile 使用 Python 3.12 slim，并从 CPU wheel index 安装固定版本的 llama-cpp-python；构建过程还会下载 ChromaDB 使用的 ONNX embedding 模型。Docker build 需要能访问配置的 Python wheel 和模型下载源。Compose 配置检查不等于镜像构建或服务启动验证。

Git LFS 跟踪 models/decider-2b-v11-Q4_K_M.gguf（约 1.27 GB）。.dockerignore 排除 models/*.gguf；Compose 在运行时将宿主机 models/ 只读挂载到容器 /app/models。baseline 默认不加载权重。启用 local 前确认 LFS 文件已实际下载。

## 3. baseline 与 Mapika local

### 默认 baseline

.env.example 中默认：

```env
ECHOMIND_DECISION_BACKEND=baseline
```

该模式执行三路意图融合，不加载 Mapika GGUF。LLM、向量和 Pattern 分支的默认融合权重是 0.7 / 0.2 / 0.1。当前 Anthropic SDK 没有 embeddings 资源，因此默认向量分支是本地 256 维字符 n-gram 哈希相似度。

### 可选 local

确认已经运行 git lfs pull，再修改 .env：

```env
ECHOMIND_DECISION_BACKEND=local
ECHOMIND_LOCAL_DECISION_PROVIDER=mapika_gguf
ECHOMIND_DECIDER_MODEL_PATH=./models/decider-2b-v11-Q4_K_M.gguf
ECHOMIND_DECIDER_N_CTX=2048
ECHOMIND_DECIDER_N_THREADS=6
ECHOMIND_DECISION_TRIGGER_CONFIDENCE=0.65
ECHOMIND_LLM_PRIORITY_CONFIDENCE=0.85
```

Compose 会将容器内模型路径固定为 /app/models/decider-2b-v11-Q4_K_M.gguf。决策器在必要时惰性加载；未失败且置信度达到优先阈值的 LLM 结果直接采用。融合结果为 other、置信度低于触发阈值或三路结果冲突时，local 才复核。模型异常、缺失、拒判或超时均回退 baseline，并在 /chat 返回来源、状态和耗时字段。

Mapika 权重来源为 [Mapika/decider-2b-GGUF](https://huggingface.co/Mapika/decider-2b-GGUF)，许可证 Apache-2.0，项目保留上游许可证文本。OpenJevProvider 只适配自托管的 OpenJev-compatible HTTP 服务，不是官方 JEV API；目前没有官方 JEV 连接。

## 4. 调用对话与检查轨迹

普通请求：

```bash
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"请问订单目前配送到哪里了？","user_id":"demo_user","conv_id":"demo_conversation"}'
```

/chat 返回的 request_id 可用于查询工具轨迹：

```bash
curl http://localhost:8000/trace/tool/<request_id>
curl "http://localhost:8000/trace/tools?limit=20"
```

响应会包含 intent、intent_group、intent_source_scores、intent_decision_source、intent_decision_status、primary_agent、supporting_agents、tools_used、routing_reason、escalated 和 latency_ms。工具轨迹位于当前进程内存中，服务重启后不保证保留。

### 物流纠纷演示边界

物流工具只读取 data/mock_logistics.json 中的演示运单，不访问顺丰、菜鸟或其他真实物流平台。运单号示例均为合成 mock 编号。可以先用纠纷描述触发 Logistics 路由；缺少 tracking_no 时 Agent 会追问。提供 fixture 中存在的运单号后，工具输出的 source 为 local_mock。

升级候选默认要求：疑似丢件意图、本地模拟记录停滞不少于 7 天，以及最近五条历史消息中至少两条同类用户追问。后一项是无时间戳历史上的计数代理。满足条件时系统将结果交给 EscalationAgent 并生成应用内交接说明，响应标记为升级；它不会创建真实工单，也不会联系人工客服队列。修改阈值可设置 ECHOMIND_LOGISTICS_LOST_DAYS_THRESHOLD 和 ECHOMIND_LOGISTICS_MIN_FOLLOWUPS。

真实物流政策示例 data/demo_docs/logistics_demo_policy.md 明确标为模拟材料。需要验证检索时，先导入知识库，再询问 Agent；知识是否检索由 Agent 按需决定。

## 5. RAG 与知识库

所有 LLM Agent 都可以通过白名单工具 search_knowledge_base 查询知识库，Agent 根据用户问题自行决定是否调用。/chat 不会按意图预检索。检索工具执行查询改写、多个查询召回、合并去重和 LLM 重排，并经 ToolManager 缓存和熔断处理。

### 查看文档数

```bash
curl http://localhost:8000/knowledge/stats
```

### 导入物流模拟说明

```bash
curl -X POST http://localhost:8000/knowledge/upload \
  -F "file=@data/demo_docs/logistics_demo_policy.md"
```

### 导入结构化样例

```bash
curl -X POST http://localhost:8000/knowledge/upload \
  -F "file=@data/demo_docs/sample_knowledge.json"
```

### 独立测试检索

```bash
curl -X POST "http://localhost:8000/search?query=物流签收争议需要收集什么信息&top_k=3"
```

知识库不可用时，检索工具会返回错误或回退信息供 Agent 处理。用户上传材料前应确认来源与适用范围；物流演示政策本身不是外部权威政策。

## 6. 动态 Skills

| Skill | 目录 | 适用 Agent |
|---|---|---|
| 通用客服 | skills/general_customer_service/ | general |
| 技术支持 | skills/technical_support/ | technical |
| 账单服务 | skills/billing_support/ | billing |
| 物流纠纷 | skills/logistics_support/ | logistics |

查看 Skill 状态和解析错误：

```bash
curl http://localhost:8000/skills
```

修改 Skill 后热加载：

```bash
curl -X POST http://localhost:8000/skills/reload
```

Skill 使用 front matter 中的 name、description、keywords、agents、enabled 字段。只有启用且 Agent 类型匹配、用户消息命中关键词的内容才会注入提示词；总长度受提示预算限制。EscalationAgent 当前走确定性交接输出，不执行 LLM prompt。

## 7. 监控与评测

| 路径 | 用途 |
|---|---|
| GET /monitor | Agent 与工具运行统计、告警和路由惩罚 |
| GET /metrics | Prometheus 指标 |
| POST /eval/run | 意图与端到端回复评测、Judge 评分和回归比较 |
| GET /trace/tool/{request_id} | 按 request_id 查看工具调用轨迹 |

Prometheus 在 Compose 中通过 config/prometheus.yml 抓取 API 指标。历史固定意图评测位于 data/eval/g4_intents_v1.json 和 data/eval/g4_results/。结果报告包含旧标签与细分物流标签的不同统计范围；P95 是意图识别耗时，不是 /chat 端到端耗时。完整样本量、G3 执行环境缺项和历史差异见项目根目录 README。

POST /eval/run 会更新 EVAL_BASELINE_PATH 对应的回归基线文件。固定 benchmark 默认生成新的 reproduction_<variant>.json；复跑时指定新的 G4_OUTPUT_PATH，避免覆盖已有历史记录。

## 8. 本机 Python 依赖

Docker 使用 Python 3.12 slim。直接运行需 Python 环境、Redis 和 ChromaDB 服务，并需根据本机平台安装 llama-cpp-python CPU wheel。仓库依赖已固定在 requirements.txt：

```bash
python -m pip install --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu -r requirements.txt
```

启动 API：

```bash
python -m uvicorn api.main:app --host 0.0.0.0 --port 8000
```

设置 ANTHROPIC_API_KEY、REDIS_URL、CHROMA_HOST、CHROMA_PORT 等环境变量。若启用 local，设置 ECHOMIND_DECISION_BACKEND=local 并确认模型文件路径可读。

## 9. 测试

在具备仓库依赖和 pytest 的 Python 环境中，从服务根目录运行：

```bash
python -m pytest -q
```

测试覆盖意图决策回退、物流 Agent 与 mock 工具、工具轨迹/并发隔离、路由降级、知识库幂等性等场景。测试结果与当前运行环境应一并记录。

## 10. 排障提示

- **/health 未就绪**：检查 docker compose ps、应用日志、Redis/ChromaDB 健康状态及 API Key 是否有效。
- **本地模型未加载**：确认 git lfs ls-files 显示权重已下载、模型路径存在且 /app/models 只读挂载有效；baseline 模式不会加载模型。
- **物流样例未命中**：确认使用 data/mock_logistics.json 中的演示编号；未命中仅代表本地 fixture 无此记录。
- **/search 没有结果**：查看 /knowledge/stats，确认已导入文档；/chat 中的知识工具调用由 Agent 判断。
- **工具轨迹找不到**：按响应中的 request_id 查询，并确认请求仍在当前进程最近 200 条记录中。
